# Ресурсы по OAuth 2.1 для обучения AI и разработки проектов

Этот документ содержит структурированный набор источников по OAuth 2.1: от официальных спецификаций до практических руководств и анализа безопасности. Материал предназначен для формирования базы знаний AI-агента и использования в качестве справочника при разработке веб-приложений.

---

## 📜 1. Официальная спецификация и документы IETF

*Первоисточники, определяющие стандарт.*

*   **Черновик спецификации OAuth 2.1 (IETF Datatracker)**: Основной документ (draft-ietf-oauth-v2-1). OAuth 2.1 консолидирует OAuth 2.0 (RFC6749) и набор лучших практик (BCP) в единый документ, не вводя новых функций.
*   **Презентации с заседаний IETF (122, 125)**: Материалы, в которых авторы стандарта объясняют цели OAuth 2.1, ключевые изменения (например, обязательное использование PKCE и запрет режима `plain`) и текущий статус документа.
*   **Сопутствующие RFC**: OAuth 2.1 включает в себя и делает обязательными требования из:
    *   **RFC 7636 (PKCE)**: Механизм Proof Key for Code Exchange.
    *   **RFC 8252 (Native Apps BCP)**: Лучшие практики для нативных приложений.
    *   **RFC 9700 (Security BCP)**: Лучшие практики по безопасности OAuth 2.0.

## 📖 2. Обзоры, сравнение с OAuth 2.0 и миграция

*Материалы, объясняющие, почему появился OAuth 2.1 и как перейти с предыдущей версии.*

*   **"OAuth 2.0 vs OAuth 2.1: What changed, why it matters, and how to upgrade" (WorkOS)**: Подробный разбор ключевых отличий. Объясняет, что OAuth 2.1 — это "курируемое обновление", которое делает безопасные практики обязательными, убирая опасные варианты (Implicit Flow, Password Grant).
*   **"6 OAuth 2.1 Changes That Will Break (and Fix) Your B2B Authentication Stack" (Security Boulevard)**: Практический взгляд на шесть ключевых изменений, которые могут "сломать" существующие реализации, и рекомендации по миграции.
*   **"OAuth 2.1 Guide: What Changed and How to Migrate" (Aembit)**: Пошаговое руководство по миграции с реалистичным графиком (около шести недель) и приоритетами: сначала устранение устаревших потоков, затем внедрение PKCE и строгого соответствия redirect URI, потом — ротация токенов.

## 🧑‍💻 3. Практические руководства по реализации и примеры кода

*Источники с конкретными шагами, фрагментами кода и готовыми репозиториями.*

*   **"OAuth 2.1 mit PKCE in Node.js: 12 Schritte" (Shattered.io)**: Пошаговое руководство по созданию OAuth-логина с PKCE на Node.js и Express. Показан полный цикл: от генерации `code_verifier` до обмена кода на токен и защиты маршрутов.
*   **`defless/OAuth-2.1-example` (GitHub)**: Учебная песочница для интеграции OAuth 2.1 с Fastify API. Репозиторий создан в образовательных целях и демонстрирует полный поток авторизации.
*   **`m-thirumal/oauth-authorization-server` (GitHub)**: Пример реализации сервера авторизации на OAuth 2.1 с использованием Spring Boot и PostgreSQL.
*   **`risan/mcp-starter` (GitHub)**: Пример создания сервера MCP (Model Context Protocol) с собственной реализацией сервера авторизации OAuth 2.1 на Rust. Демонстрирует практическое применение OAuth 2.1 для защиты AI-агентов.

## 🔒 4. Безопасность, тестирование и анализ угроз

*Материалы, необходимые для обучения безопасной реализации и проведения аудита.*

*   **"OAuth/OpenID Connect 安全评估实战：一份完整的测试用例清单"**: Практический чек-лист для тестирования безопасности, включающий проверку на открытый редирект, атаки понижения PKCE, SSRF, CSRF и управление жизненным циклом токенов.
*   **"Audience Injection Attacks" (IEEE Symposium on Security and Privacy, 2026)**: Научная статья, описывающая новый класс уязвимостей, затрагивающих OAuth 2.0, OpenID Connect, FAPI и связанные расширения.
*   **"Attacking OAuth 2.1" (Bug Bounty Podcast)**: Эпизод подкаста с анализом того, как изменения в OAuth 2.1 (обязательный PKCE, строгое соответствие redirect URI, вынос bearer-токенов из URL) влияют на поверхность атаки.

## 🤖 5. OAuth 2.1 в контексте AI и MCP (Model Context Protocol)

*Современное применение стандарта, критически важное для AI-агентов.*

*   **Спецификация безопасности MCP (modelcontextprotocol.io)**: Официальный документ, который требует, чтобы реализации MCP следовали лучшим практикам безопасности OAuth 2.1, включая обязательное использование PKCE.
*   **"Understanding Authorization in MCP" (modelcontextprotocol.io)**: Руководство по реализации безопасной авторизации для серверов MCP с использованием OAuth 2.1 для защиты конфиденциальных ресурсов и операций.

## 💎 8. Как использовать этот набор для обучения AI и разработки

1.  **Для обучения AI**: Используйте официальную спецификацию и обзорные статьи (WorkOS, Security Boulevard) для формирования базы знаний. Чек-листы по безопасности и научные статьи помогут агенту усвоить паттерны уязвимостей и корректные практики.
2.  **Для разработки проекта**: Начните с практических руководств и примеров кода (Node.js, Fastify, Spring Boot). Используйте ссылки на библиотеки для выбора стека. Обязательно интегрируйте проверки из чек-листа по безопасности на этапе тестирования. Для AI-агентов изучите спецификацию MCP.

## 3. ЦЕЛЬ

### 3.1. Что нужно получить
Веб-платформа (онлайн конструктор) OAuth 2.1 / OpenID Connect, где человек без опыта в аутентификации может пошагово, с пояснениями и подсказками, собрать необходимые файлы и выгрузки для интеграции в свой код. Платформа должна генерировать готовые конфигурационные файлы, сниппеты кода и инструкции по интеграции для различных стеков (React, Vue, Next.js, Python, Node.js, PHP, Go, Java, мобильная разработка).

### 3.2. Зачем это нужно
Малый и средний бизнес, фрилансеры и junior-разработчики не могут самостоятельно настроить OAuth 2.1 / OIDC интеграцию из-за сложности спецификации, множества потоков (authorization code, implicit, client credentials, device code) и необходимости правильно сгенерировать конфигурацию, метаданные и код. Платформа убирает порог входа: пользователь отвечает на простые вопросы, получает готовые файлы и пошаговую инструкцию.

### 3.3. Критерий успеха
Пользователь без опыта в Auth может за 5–10 минут пройти мастера конструктора, выбрать свой стек и тип приложения, получить загружаемый архив с готовыми файлами конфигурации и кода, а также текстовую инструкцию по интеграции. Все сгенерированные конфиги проходят валидацию по спецификации OAuth 2.1 / OIDC.

## 5. ПРОДУКТОВЫЙ КОНТЕКСТ (НОВЫЙ ПРОДУКТ)

- **Идея в одном предложении:** Веб-конструктор OAuth 2.1 / OIDC, который menéт пользователя от выбора типа приложения до загрузки готового архива с конфигурацией и кодом для интеграции.
- **Проблема пользователя:** Сложность настройки OAuth 2.1 / OIDC для неопытных разработчиков — не понятно какой поток выбрать, какие URL указать, как сгенерировать клиентский ID и секрет, какой код вставить в приложение.
- **Целевая аудитория:** junior-разработчики, владельцы малого бизнеса, фрилансеры, студенты, команды без dedicated security-инженера.
- **MVP-функции:**
  1. Мастер настройки OAuth 2.1 (пошаговый мастер с вопросами на русском языке).
  2. Выбор типа приложения (SPA, веб-сайт, мобильное приложение, CLI, сервер-сервер).
  3. Выбор 공급щика идентичности (Google, GitHub, Yandex, VK, кастомный OIDC).
  4. Генерация конфигурационных файлов (client_secrets.json, .env, oauth.yaml).
  5. Генерация сниппетов кода для интеграции (React, Vue, Next.js, Python/FastAPI, Node.js/Express, PHP, Go).
  6. Валидация сгенерированной конфигурации по спецификации OAuth 2.1 / OIDC.
  7. Загрузка архива (.zip) со всеми файлами и текстовой инструкцией по интеграции.
- **Аналоги и отличие:** Auth0, Okta, Keycloak — полноценные Auth-серверы (сложные, платные); наш конструктор — только генерация конфигурации и кода для клиентской стороны, бесплатно, без регистрации, с понятными пояснениями.
- **Монетизация:** не определена (MVP бесплатно).
- **Платформа:** web (браузерная платформа).
- **Сроки и бюджет:** не определены.

- Мобильное приложение конструктора (только веб).
- Интеграция с конкретными поставщиками через реальные API (только генерация конфига).

### 6.3. Допущения
- Пользователь знает базовые понятия (сайт, приложение, логин) но не знает OAuth.
- Генерация файлов происходит локально в браузере или на сервере без сохранения секретов.

| **PKCE (RFC 8252)** | — | IETF | Любой | Стандарт для публичных клиентов (SPA, мобильные), обязателен в OAuth 2.1 |

### 15.2. Что конкретно скопировать, чтобы сэкономить токены

1. **Структура конфигурационных файлов** — из Auth0/Okta документации (client_secrets.json, .env шаблоны, поля с пояснениями).
2. **Валидация redirect URIs и scopes** — из oauthlib (Python) или OAuth 2.1 RFC.
3. **Шаблоны кода интеграции** — из Passport.js / python-social-auth (как подключать OAuth к React, Vue, Express, FastAPI).
4. **Логика пошагового мастера с подсказками** — адаптировать из Auth0 Dashboard под нетехнических пользователей.
5. **Генерация ZIP-архива** — стандартные библиотеки (zipfile в Python, JSZip во фронтенде).

### 15.3. Рекомендация по следующему шагу

Изучить спецификацию OAuth 2.1 (RFC 6749 + RFC 8252 для PKCE) и OpenID Connect Discovery. Адаптировать шаблоны конфигурации из Auth0/Okta под генерацию через веб-интерфейс. Это сократит реализацию с месяцев до недель.

**Ограничение:** использовать только для изучения архитектуры и адаптации; не нарушать права авторов и условия использования поставщиков идентичности.

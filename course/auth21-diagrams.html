                        Cheat Sheet

                        OIDC + PKCE Flow

                        Современный стандарт авторизации для веб-приложений, SPA и мобильных приложений.

                        Зачем и как

                        Зачем нужен. Безопасно получает токены доступа без хранения client_secret на клиенте — в браузере или телефоне его невозможно скрыть.

                        Как работает. Использует PKCE (Proof Key for Code Exchange) — динамический ключ, создаваемый на клиенте и проверяемый на сервере.

                        Участники (глоссарий)
                        Браузер (User Agent)
                        Клиентское устройство пользователя.
                        Приложение (RP / Relying Party)
                        Ваш бэкенд или SPA (фронтенд), который доверяет серверу авторизации.
                        Сервер авторизации (AS / OpenID Provider)
                        Система проверки логина/пароля и выдачи токенов (например, Keycloak, Auth0).
                        API (Ресурс)
                        Защищённые данные и сервисы, к которым нужен доступ под токеном.
                        Ключевые параметры
                        state
                        Случайная строка для защиты от CSRF-атак. Генерируется в 1.2, сверяется при возврате (3.3) — не совпало → 400.
                        nonce
                        Случайная строка для защиты от Replay Attack. Генерируется в 1.2, возвращается в ID-токене и сверяется в 5.1.
                        code_verifier
                        Секретная строка, генерируемая клиентом (1.2), хранится в сессии, предъявляется только на /token (4.1).
                        code_challenge
                        Хэш от code_verifier (S256). Уходит в /authorize (1.3), сверяется АС при обмене (4.2).
                        Структуры данных

                        Authorization Code
                        Короткоживущая строка (1–5 минут, одноразовая). Пример:

                        codeSplxlOBeZQQYbYS6WxSbIA

                        ID Token (JWT)

                        json{ "iss": "https://auth.example.com", "sub": "1234567890", "aud": "my-client-id", "exp": 1698765432, "iat": 1698761832, "nonce": "abc123xyz" }

                        Access Token (JWT)
                        Передается в заголовке Authorization: Bearer ***

                        json{ "sub": "1234567890", "scope": "openid profile email", "roles": ["user", "admin"], "exp": 1698765432 }

                        «→ шаг N» открывает этот шаг в диаграмме «Основной вход».
